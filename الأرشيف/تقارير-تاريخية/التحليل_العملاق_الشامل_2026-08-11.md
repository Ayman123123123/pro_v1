## 0) الخلاصة التنفيذية (اقرأ هذا أولاً)

**مشروعك ليس مشروع أندرويد عادي** — هو منظومة سيادية كاملة من 5 طبقات تبنيها مرة واحدة وتشغّلها كمنتج:

| الطبقة | المجلد القانوني | التقنية | الحالة الحالية |
|---|---|---|---|
| **1. Android** | `red-app/` (`:app`) | Kotlin + Compose + Signal Protocol | **متقدم جداً** — على أحدث خط AGP 9.2 / Kotlin 2.3.10 |
| **2. Backend** | `backend-server/` | Spring Boot + Kotlin JVM + Postgres/Mongo/Redis | **يحتاج ترقية عاجلة** — على خط 3.5 المنتهي |
| **3. Admin Dashboard** | `admin_dashboard/` | React 19 + Vite 7 + Ant Design 6 | **ممتاز** — على أحدث جيل |
| **4. SFU** | `media-sfu/` | Node.js + mediasoup | **جيد** — Node يحتاج تثبيت LTS 24 |
| **5. Infra** | `docker-compose.yml` + `pstn-asterisk` + `nginx` + `coturn` | Docker | **مستقر** — صور 2024-2025 تحتاج تحديث طفيف |

**الحكم العام:** 82% من المشروع على أحدث إصدار مستقر بالفعل. الـ 18% المتبقي هو **Backend Spring Boot 3.5 (EOL)** و **Gradle/Kotlin** اللذان صدر لهما جيل جديد بعد تثبيت مشروعك.

**التوصية الذهبية — 3 ترقيات فقط بدون أي تعارض:**

1. **Backend:** `3.5.16 → 4.0.7` (قفزة آمنة، Java 21 كما هو) — ثم `4.1.0` بعد استقرار
2. **Android toolchain:** `Kotlin 2.3.10 → 2.3.21` + `KSP 2.3.11` + `Gradle 9.4.1 → 9.7.0` + `AGP 9.2.1 → 9.3.0`
3. **Node/Admin:** تثبيت `Node 24 LTS` + `React 19.2.8` + تحديث صور Docker (Postgres 16.9 / Redis 7.4)

> ⚠️ ما **لا** نلمسه الآن: `libsignal 0.99.1 → 0.100.0` (يتطلب rollout بروتوكولي)، `Compose BOM 2026.06.01` (هو الأحدث أصلاً)، `Java 21` (يبقى كما هو — لا حاجة لـ 25/26 الآن)

**المجلدات خارج الـ graph (مراجع فقط، لا تدخل البناء):** `app/` (Signal gold mine), `android/` (AQYAL), `app-android/` (DevelopedChat), `core/`, `lib/`, `feature/`, `demo/`, `benchmark/` … — وجودها لا يعني أنها تُبنى.

### البروتوكول الموحد
`shared-proto` هو **المصدر الوحيد للحقيقة** بين Android و Backend — أي تغيير فيه يتطلب إعادة توليد في الطرفين. هذا فصل معماري ممتاز يحميك من drift.

### الأمان السيادي (نقاط قوة)
- مفاتيح Signal الخاصة لا تغادر الجهاز (PersistentSignalProtocolStore على SQLCipher)
- موافقة إدارية ثنائية (حساب + جهاز) قبل أي وصول
- TLS pinning قابل للحقن عبر `RED_TLS_PINS`
- Argon2id عبر BouncyCastle على Backend
- mediasoup SFU مصادق عليه بـ JWT_SECRET (أقل من 32 حرف = فشل إقلاع)
- حلّ race التجديد في `admin_dashboard/src/api.ts` (singleton `rotating` يمنع طرد Admin عند `Promise.all`)

**C3. كود — تغييرات Boot 4 المتوقعة:**
- `spring-boot-starter-opentelemetry` جديد (اختياري)
- `spring.mvc.api-version` جديد (لا يمسك)

**C4. بعد استقرار 4.0.7 (أسبوعين):**
```kotlin

```
