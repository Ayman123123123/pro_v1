# 🏛️ القرار المعماري الحاسم — "استراتيجية منجم سيجنال" (Signal Gold Mine)
### RED Ultimate — بدون دومين خارجي، سيرفر محلي فقط — 2026-08-04

---

## 1) الواقع الأول: سيرفر محلي بدون دومين

- كل شيء يعمل بعناوين IP محلية:
  - الخادم: `http://192.168.1.50:8080` (أو أي IP لجهاز السيرفر)
  - WebSocket: `ws://192.168.1.50:8080/ws/master`
  - MinIO: `http://192.168.1.50:9000` — SFU: `ws://192.168.1.50:4000`
  - أستريكس: `192.168.1.50:5060` — Dinstar: `192.168.1.100`
- **لا حاجة لدومين إطلاقاً.** التطبيق يعرف عنوان السيرفر من إعداد قابل للتعديل (أو QR سريع).
- ملاحظات تقنية فقط:
  - لا TLS رسمي → نستخدم HTTP محلياً، ويمكن لاحقاً شهادة ذاتية (self-signed)
  - الهواتف خارج الشبكة المحلية لن تصل — هذا تصميم "شبكة داخلية سيادية" مقصود

**الحقيقة الحاسمة:** خادم سيجنال الرسمي (signal-server) **غير قابل للتشغيل محلياً**: يحتاج دومين + شهادات TLS + DynamoDB + S3 + Redis Cluster + Twilio + خدمات مصغرة عديدة. أي مسار يعتمد على "بروتوكول سيجنال الكامل" مستحيل عملياً هنا.

## 2) تحليل الخيارين المطروحين

### الخيار (أ): "جلب كل ميزات سيجنال وجعلها لنا بالكامل"
- ✅ الميزات **موجودة فعلاً** في المستودع (الكود الكامل 5,825 ملفاً في app/src/main)
- ❌ لكن أغلبها **ميت بدون سحابة سيجنال**:

| ميزة سيجنال | تعتمد على سحابة سيجنال؟ |
|---|---|
| التسجيل برقم الهاتف / SMS / مكالمة تحقق | ✅ نعم (خوادمهم + Twilio) |
| الإشعارات الفورية FCM | ✅ نعم (Google) |
| النسخ الاحتياطي v2 السحابي | ✅ نعم |
| CDN الصور الرمزية/الوسائط | ✅ نعم |
| المجموعات v2 (Key Transparency / SGS) | ✅ نعم |
| usernames / الدليل / المدفوعات | ✅ نعم |
| التشفير E2EE (libsignal) | ❌ **لا — يعمل محلياً 100%** |
| قاعدة البيانات + المخططات | ❌ لا — محلية |
| معالجة الوسائط (Glide/Media3/محرر) | ❌ لا — محلية |
| واجهات Compose / الشاشات | ❌ لا — محلية |

- **النتيجة:** "فورك سيجنال ميت" — واجهة ضخمة تعرض أخطاء اتصال في كل شاشة، وإعادة تسمية سطحية لا تجعله "ملكنا" فعلاً.

### الخيار (ب): "نخليها ونصلحها ونوجد التطبيق ونحل المشاكل"
- ✅ أخطاء الترجمة قابلة للإصلاح (خطة ACTION_PLAN_AR.md)
- ❌ **لكن الجدار الحقيقي بعده:** تطبيق سيجنال يتكلم **بروتوكول خادم سيجنال** (WebSocket +v1/messages، prekeys، profile، storage service...)، بينما خادمك يتكلم **RedProtos** — بروتوكولان مختلفان تماماً لا يلتقيان:
  - تشغيله = إعادة بناء خادم سيجنال كاملاً في backend-server (شهور + يستحيل بلا دومين)
  - تبقى حرب الواجهتين على MainActivity (الفوضى الحالية)
  - 95% من ميزات سيجنال ستبقى معطلة بلا سحابته

## 3) المقترح الأقوى: "RED أصلي فوق منجم سيجنال" ⭐

**الفكرة الجوهرية:** لا نجعل سيجنال هو الهيكل، ولا نرميه — بل **ننقب فيه عن الذهب** ونبني تطبيق RED أصلياً رشيقاً يتكلم بروتوكولنا فقط، ويعمل محلياً من اليوم الأول.

```
┌─────────────────────────────────────────────┐
│  تطبيق RED (واجهة AQYAL العربية — جاهزة)      │
│  ─────────────────────────────────────────── │
│  • محرك التوصيل RED (UUID v7 + ACK + Retry)   │
│  • RedWebSocketClient ← خادمنا (RedProtos)    │
│  • تشفير E2EE: libsignal-client (Rust)        │ ← منجم سيجنال
│  • قاعدة بيانات SQLCipher + المخططات          │ ← منجم سيجنال
│  • الوسائط: Glide + Media3 + محرر الصور       │ ← منجم سيجنال
│  • التسجيل: طلب → موافقة المدير (لا SMS)      │
│  • المكالمات: WebRTC ← SFU المحلي + Dinstar   │
└─────────────────────────────────────────────┘
         ↕ بروتوكول واحد (RedProtos)
┌─────────────────────────────────────────────┐
│  backend-server (Spring Boot — موجود)        │
│  + admin_dashboard (React — موجود)           │
│  + media-sfu (mediasoup — موجود)             │
│  + pstn-asterisk + Dinstar UC2000            │
└─────────────────────────────────────────────┘
```

### لماذا هذا أقوى من الخيارين؟
1. **يعمل من اليوم الأول** محلياً (IP فقط — لا دومين)
2. **بروتوكول واحد** بين الهاتف والخادم — تنتهي فوضى البروتوكولين
3. **التشفير الحقيقي يبقى معنا**: libsignal = نفس تشفير سيجنال (Double Ratchet + Kyber ما بعد الكم) ويعمل بدون أي سحابة — "ملكنا" فعلاً
4. **كل طبقة RED الحالية تتكامل بسلاسة**: الموافقة الإدارية، القصص، Dinstar، اللوحة، SFU
5. **واجهة واحدة** (AQYAL) — تنتهي حرب الـ MainActivity للأبد
6. **مشروع رشيق**: من 5,825 ملفاً إلى ~200 ملفاً نتحكم فيها كلها — أسهل في الإصلاح والاختبار والتطوير
7. **الترخيص سليم**: AGPLv3 + NOTICE موجود — ننقل الكود مع الإسناد القانوني

## 4) خريطة نقل الذهب من سيجنال

### نأخذه (يعمل محلياً بلا سحابة)
| الكنز | مكانه الآن | الاستخدام في RED |
|---|---|---|
| libsignal-client (E2EE + Kyber) | `libs.libsignal.android` (مكتبة) | طبقة التشفير في التطبيق |
| SQLCipher + schema + migrations | `app/src/main/java/.../database` | قاعدة التطبيق المحلية |
| معالجة الوسائط (Glide, Media3, محرر) | `lib/glide`, `lib/video`, `lib/image-editor` | إرسال صور/فيديو عبر MinIO |
| مفاهيم الشاشات (نسخ وإعادة تصميم) | ملفات Signal UI | مرجع تصميم لواجهة AQYAL |
| الاختبارات (694 androidTest) | `app/src/androidTest` | نقل المفيد منها لطبقة RED |
| أدوات الجودة (fast-lint, wire-handler, reproducible-builds) | الجذر | تستخدم كما هي |

### نتركه (يحتاج سحابة سيجنال — مستحيل محلياً)
- التسجيل برقم الهاتف / SMS / مكالمة تحقق ← **نستبدله بالموافقة الإدارية**
- FCM Push ← **نستبدله بـ WebSocket دائم + خدمة أمامية**
- النسخ الاحتياطي v2 السحابي ← **نسخة احتياطية محلية مشفرة (Backup v1 concept)**
- CDN الصور الرمزية ← **MinIO المحلي**
- المجموعات v2 / Key Transparency ← **مجموعات RED بسيطة (GroupEntity موجودة)**
- المدفوعات / usernames / الدليل ← **غير مطلوبة في المنظومة السيادية**

## 5) التنفيذ بفرق الوكلاء (Claude — أقوى النماذج)

نعمل كفرق وكلاء متوازية، كل وكيل يسلم كوداً **يبني ويعمل** + تحقق:

| الوكيل | المسؤولية | المدة المقدرة |
|---|---|---|
| **W1 — وكيل الخادم** | إصلاح أخطاء backend-server العشرة + تشغيل + اختبار `/health` وWebSocket | يوم 1 |
| **W2 — وكيل اللوحة** | إصلاح admin_dashboard (signalFilled + Dockerfile) + مطابقة endpoints | يوم 1–2 |
| **W3 — وكيل نواة RED** | بناء :app الجديد: واجهة AQYAL + RedWebSocketClient + محرك التوصيل + Room + MinIO | يوم 2–3 |
| **W4 — وكيل التشفير** | دمج libsignal-client كطبقة E2EE فوق RedProtos (إدارة الجلسات/المفاتيح) | يوم 3–5 |
| **W5 — وكيل VoIP/PSTN** | ربط WebRTC عبر media-sfu + Dinstar (اختيار تلقائي إنترنت/خلوي) | أسبوع 2 |
| **W6 — وكيل الأمن** | JWT موقّع + HandshakeInterceptor + أسرار .env + TLS ذاتي + allowBackup=false | يوم 4–5 |

**ملاحظة على الوكلاء:** تُنفّذ الأدوار بمسارات ملفات واختبارات قبول منفصلة لمنع تعارض التعديلات. اختيار النموذج الفعلي لكل جلسة تديره منصة Arena؛ لا ينبغي أن تعتمد سلامة المشروع على اسم نموذج بعينه.

## 6) القرار المعتمد — 2026-08-04

اعتمد مالك المشروع القرارات التالية:

1. **الاستراتيجية:** RED أصلي + منجم سيجنال.
2. **الواجهة:** AQYAL العربية كواجهة RED الرسمية.
3. **الهوية:** لا رقم هاتف، لا SIM، لا SMS؛ `username + password + RED ID`.
4. **التفعيل:** كل حساب جديد `PENDING` ولا يحصل على جلسة دخول قبل موافقة مسؤول من لوحة الإدارة.
5. **التشغيل الأول:** خادم محلي بلا دومين، مع الانتقال إلى TLS ودومين عند الإطلاق العام.
6. **البدء:** W1 — إصلاح الخادم ونظام التسجيل والموافقة وتوحيد البروتوكول.

> لا يجوز إعادة إضافة تسجيل برقم الهاتف أو بروتوكول محادثات ثانٍ دون قرار معماري جديد موثّق.
