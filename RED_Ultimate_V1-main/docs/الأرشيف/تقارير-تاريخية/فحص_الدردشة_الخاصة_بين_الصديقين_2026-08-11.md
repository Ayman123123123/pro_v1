# 💬 فحص الدردشة الخاصة (1:1 بين صديق وصديق) — مسار كامل

> **التاريخ:** 2026-08-11
> **النطاق:** سير العمل الكامل للدردشة الخاصة من إضافة الصديق → فتح المحادثة → الإرسال → الاستقبال → العرض، في تطبيق «يونس» (`red-app` + `backend-server`).

---

## 1) مسار الدردشة الخاصة الكامل (خطوة بخطوة)

### الخطوة 1 — إضافة صديق (Friend Request)
```
المستخدم → DirectoryViewModel.search(username/redId) → GET /api/directory/search
        → directory.request(profile) → POST /api/contacts/requests/{redId}
الطرف الآخر → accepts عبر resolve(request, accept=true) → POST /api/contacts/requests/{id}/accept
```
- ✅ يتم عبر **البحث باسم مستخدم** أو **معرّف**.
- ✅ يوجد أيضًا `ShareRedIdSheet` (مشاركة المعرف QR/نص) و`QrScannerSheet` (مسح).
- ✅ إزالة/حظر/بلاغ متاحة.

### الخطوة 2 — فتح المحادثة
- من قائمة الأصدقاء: `onClick { target = person.redId }`
- أو من قائمة المحادثات (`conversations`): `onClick { target = conv.peerId }`
- **معرّف المحادثة:** `conversationId(account.redId, target)` = SHA-256(فرز([red1, red2])) أول 32 حرفًا.
  - ✅ **الترتيب لا يهم** (يُفرز قبل الهاش) → الطرفان يحصلان على نفس المعرّف.

### الخطوة 3 — الإرسال
```
إرسال زر → RichMessage(action="MESSAGE", text, ...) → sendRichText
        → sendPayload → RedConnectionService → signal.encrypt(target, payload)
        → socket.sendEncrypted(target, conversation, "RICH_TEXT", deviceId, envelope)
        → RedProtos.ChatMessage (receiverId = target)
التخزين: saveLocalHistory(... outgoing=true) + onMessageStored(conversation, target, preview, ..., isIncoming=false)
```
- ✅ مشفّر عبر **libsignal PQXDH/Double Ratchet**.
- ✅ يُخزَّن محليًا + تُحدَّث المحادثة.

### الخطوة 4 — الاستقبال
```
WebSocket onEnvelope → MESSAGE
  → saveIncomingMessage (ciphertext)
  → signal.decrypt(senderId, senderDeviceId, ciphertextType, payload)
  → saveLocalHistory(conversationId, senderId, plaintext, ...)   [1:1 فقط]
  → onMessageStored(conversationId, senderId, preview, ..., isIncoming=true)
  → DecryptedMessageBus.publish → الواجهة تُضيف للقائمة
  → socket.acknowledge(...DELIVERED)
  → إشعار (إن مفعّل)
```
- ✅ يُفك التشفير ويُعرض فورًا.
- ✅ إيصال قراءة: الواجهة تستدعي `markRead` عند عرض رسالة واردة (إن كانت readReceipts مفعّلة).
- ✅ مؤشر كتابة عبر `TypingEventBus`.

## 3) العيوب الحقيقية المكتشفة (مهم جدًا)

### 🔴 الخلل 1 (الأهم): **البحث بمعرّف YNS لا يعمل**
**الموقع:** `backend-server/.../PublicDirectoryController.kt` (سطر 20)
```kotlin
val matches = if (term.startsWith("RED-", ignoreCase = true)) {
    users.findByRedId(term.uppercase())   // ← فقط RED-
} else {
    users.findByUsernameIgnoreCase(term)  // ← يعامل أي شيء آخر كاسم مستخدم
}
```
**المشكلة:** نظامك **الجديد** يولّد معرفات بصيغة **`YNS-XXXX-XXXX`** (من `RedIdGenerator.kt`). لكن هذا الكود يتحقق فقط من `RED-`. لذلك:
- البحث بـ **`YNS-ABCD-EFGH`** → لا يطابق `RED-` → يُعامَل كاسم مستخدم → **لن يجد الصديق!**
- لا يمكن إضافة صديق **بمعرّف YNS** عبر البحث المباشر.

**النتيجة:** مستخدمو `YNS-*` الجدد **لا يستطيعون إضافة أصدقاء بمعرفهم** — عطل حقيقي في الدردشة الخاصة.

**الإصلاح:** تمديد الشرط ليشمل `YNS-`:
```kotlin
val matches = if (term.startsWith("RED-", ignoreCase = true) || term.startsWith("YNS-", ignoreCase = true)) {
    users.findByRedId(term.uppercase()).filter { it.status == AccountStatus.APPROVED }
} else {
    users.findByUsernameIgnoreCase(term).filter { it.status == AccountStatus.APPROVED }
}
```

### 🟠 الخلل 2: **التعديل/الحذف لا يثبّتان على التخزين**
- عند **استقبال** رسالة `EDIT`/`DELETE` (كـ RICH_TEXT)، يعاملها `onEnvelope` كرسالة جديدة ويحفظها في `local_history`.
- التعديل/الحذف يُطبَّق **في الذاكرة فقط** عبر `resolveRichMessages` في الواجهة.
- **بعد إعادة فتح المحادثة:** تعود النسخة القديمة / الرسالة المحذوفة.
- **الإصلاح:** في `onEnvelope`، عند فك `RichMessage` بـ `action="EDIT"` تحديث السجل الأصلي، وبـ `action="DELETE"` حذفه.

### 🟡 الخلل 3: **شريط عنوان الطرف في الدردشة يعرض معرّفاً مختصراً**
- عند غياب صورة/اسم جهة (لم تُحمَّل بعد من الدليل)، يعرض `activePerson?.displayName ?: target` — أي المعرّف الكامل الطويل.
- مقبول لكن يُفضَّل إظهار الاسم من الدليل فورًا (تحميل تلقائي).

## 6) الاستنتاج

**الدردشة الخاصة في «يونس» متقدمة وظيفيًا**: تشفير حقيقي، ردود، تعديل، حذف للجميع، إعادة توجيه، رسائل مؤقتة، إيصالات قراءة، مؤشر كتابة، مكالمات، رمز أمان.

**لكن هناك خللان حقيقيان:**
1. **`YNS-` غير مدعوم في البحث** → المستخدمون الجدد لا يضيفون أصدقاء بمعرفهم (عطل حرج).
2. **التعديل/الحذف غير مثبّتين** → الرسائل "المعدّلة/المحذوفة" تعود بعد إعادة فتح المحادثة.

**إصلاح الخللين = أولوية قصوى لضمان عمل الدردشة الخاصة بشكل صحيح.**
