# ميثاق المنتج — يونس السيادي / RED Sovereign

> **الحالة:** مصدر قرار للمنتج والتنفيذ.  
> **المبدأ:** لا نبني نسخة من WhatsApp أو Telegram أو Facebook أو X. نبني نظام تواصل سيادي محلي يملك سبباً واضحاً لوجوده، ويصلح للاستخدام اليومي قبل توسيع الميزات.

---

## 1. الوعد للمستخدم

**يونس** هو مساحة تواصل شخصية ومجتمعية تعمل بهوية RED مستقلة، لا تتطلب رقم هاتف أو SIM أو بريد للتسجيل، وتحفظ طبقة المحادثات الخاصة ومفاتيحها على أجهزة المستخدمين فقط.

المستخدم يجب أن يفهم هذا الوعد في جملة واحدة:

> «أنا أملك هويتي، محادثاتي الخاصة لا يقرأها الخادم، ومجتمعي يعمل من بنيته المحلية وليس من منصة إعلانية.»

---

## 2. ما الذي يميز يونس فعلياً؟

### أ. هوية سيادية بدل الاعتماد على رقم الهاتف

- معرّف يونس قابل للقراءة والمشاركة والإملاء هاتفيًا: خمسة أرقام مثل `12345`.
- لا SMS OTP ولا SIM ولا phonebook scraping كشرط للانضمام.
- الحساب والجهاز يمران بموافقة واضحة عند التشغيل السيادي المغلق.
- الجهاز يملك شهادة تفويض وهوية تشفيرية مستقلة.

### ب. طبقتان لا تخلطان الخصوصية بالاجتماعيات

| الطبقة | طبيعتها |
|---|---|
| المحادثات والملفات الخاصة | E2EE، مفاتيح خاصة لا تغادر Android، خادم يوجه ciphertext فقط |
| القصص والمجتمع والمنشورات العامة | محتوى اجتماعي صريح السياسة، قابل للإدارة والمراجعة، وليس موصوفاً كـE2EE |

هذا الفصل يمنع الادعاءات الأمنية المضللة ويعطي المستخدم تحكماً واضحاً.

### ج. Local-first حقيقي

- يعمل على LAN والبنية الذاتية الاستضافة أولاً.
- اكتشاف الخادم المحلي Development-only وبهوية خادم قابلة للتحقق.
- Docker deployment واضح، بلا خدمات سحابية إلزامية.
- مكالمات RED عبر WebRTC/SFU، وPSTN عبر DINSTAR مسار منفصل ومصرح به فقط.

### د. إدارة قابلة للمساءلة وليست مراقبة خفية

- كل إجراء حساس إداري له Audit Trail.
- لا تسجل محتويات E2EE أو مفاتيحها أو كلمات المرور أو أرقام الاتصال في audit logs.
- صلاحيات واضحة: مسؤول، مشغل عتاد، مشرف مجتمع، مستخدم.

---

## 3. معايير «أفضل» من التطبيقات الكبرى

لا نقيس النجاح بعدد التبويبات. نقيسه بهذه المعايير:

1. **أوضح:** يعرف المستخدم أين تكون رسالته مشفرة وأين يكون منشوره عاماً.
2. **أسرع:** فتح المحادثة والرسالة والصورة يحصلان بسرعة حتى مع شبكة متقطعة.
3. **أكثر خصوصية:** لا رقم هاتف كمعرف علني، لا إعلانات، لا SDK تتبع.
4. **أكثر ثقة:** كل حساب/جهاز/إجراء إداري له حالة ومصدر تفويض مفهوم.
5. **أكثر سيادة:** يمكن تشغيله داخل منشأة أو مجتمع أو شبكة مستقلة.
6. **أكثر أناقة:** عربي RTL أصيل، وضع داكن متقن، سهولة وصول، ومسارات بسيطة.
7. **أكثر صراحة:** لا ميزة توصف بأنها «مكتملة» قبل build واختبار جهازين وتشغيل فعلي.

## 4. تجربة المستخدم الأساسية

### تدفق الانضمام

```text
إنشاء RED ID
→ إنشاء مفاتيح الجهاز محلياً
→ طلب موافقة
→ انتظار واضح ومفهوم
→ دخول إلى محادثات/مجتمع/مكالمات بحسب الصلاحيات
```

### الشاشات الخمس الأساسية

1. **المحادثات:** رسائل E2EE، حالة وصول، ملف مشفر، بحث محلي، حالة اتصال.
2. **المكالمات:** صوت/فيديو RED، سجل واضح، رنين متعدد الأجهزة، تحكم بالمايك والكاميرا.
3. **المجتمع:** Feed وقصص بوسم واضح «عام/مجتمعي» وليس «خاصاً مشفراً».
4. **الدليل:** البحث عن RED ID، طلبات جهات الاتصال، block/report، مفاتيح أمان.
5. **الهوية والإعدادات:** الأجهزة المصرح بها، بصمة الأمان، جلسات، خصوصية، بيانات محلية.

## 5. تعريف الإصدار الأول الحقيقي

لا يخرج Alpha قبل اجتياز كل ما يلي:

### مسار شخصي مشفر

- مستخدمان معتمدان وجهازان معتمدان.
- تسجيل دخول وتجديد جلسة وإبطال جهاز.
- رسالة نصية E2EE مع ACK وdelivered/read.
- انقطاع اتصال ثم sync سليم بلا تكرار.
- مرفق مشفر يرفع وينزل ويتحقق من SHA-256.
- block يمنع الرسائل وtyping وpresence.

### المكالمات

- مكالمة صوتية بين جهازين.
- مكالمة فيديو بين جهازين.
- رنين أجهزة المستلم المعتمدة.
- لا يستطيع حساب ثالث تغيير call state.
- اختبار Wi-Fi وبيانات هاتف وانقطاع اتصال.

### الإدارة

- موافقة/رفض حساب وجهاز.
- revoke جهاز يوقف token وWebSocket.
- audit لكل إجراء حساس.
- لوحة إدارة لا تخزن refresh token دائماً.

### بنية

- HTTPS/WSS للإنتاج.
- لا MinIO/Mongo/Postgres/Redis مكشوفة للعامة.
- backup مشفر واختبار restore.
- build متكرر لـAndroid والخادم واللوحة.

## 6. ما لن نفعله الآن

- نسخ كل ميزة من كل منصة منافسة.
- إطلاق stories/feed/live/conference قبل إثبات الرسائل والمكالمات الخاصة.
- وصف محتوى اجتماعي عام بأنه E2EE.
- تشغيل SFU room access بناء على roomId فقط.
- ربط PSTN بالمراسلة الخاصة أو تقديمه كبديل عن RED VoIP.
- إضافة ذكاء اصطناعي أو blockchain أو وعود «مقاومة كمومية» بلا نموذج تهديد واختبار.

## 7. خارطة التنفيذ

| المرحلة | الهدف القابل للقياس |
|---|---|
| A — الثقة والبناء | JDK/SDK/Docker، build نظيف، CI، secrets، HTTPS |
| B — القلب الشخصي | identity، device approval، E2EE messages، attachment، sync |
| C — المكالمات | call state machine، multi-device ring، TURN، history، device tests |
| D — المجموعات وSFU | room capability، group ACL، mediasoup client حقيقي، moderation |
| E — المجتمع | feed/stories بسياسة خصوصية ومراجعة واضحة |
| F — PSTN المؤسسي | DINSTAR/Asterisk على عتاد حقيقي مع quota/audit/operational controls |

---

## 8. بوابة كل ميزة

أي ميزة جديدة لا تدمج قبل توفر:

1. Owner واضح.
2. Threat model مختصر.
3. API/Proto contract واضح.
4. اختبارات success/failure/authorization.
5. تصميم RTL والوصولية.
6. telemetry أو audit مناسب من دون تسريب خصوصية.
7. build + runtime evidence.

---

## 9. القرار التقني الحالي

- المصدر Android المنتج: `red-app/` فقط.
- المصدر Backend المنتج: `backend-server/` فقط.
- لوحة الإدارة: `admin_dashboard/` فقط.
- العقد المشترك: `shared-proto/`.
- `app/` و`android/` و`app-android/` مصادر تاريخية حتى يقرر نقل جزء منها رسمياً مع اختبار.

هذا الميثاق يمنع توسعاً عشوائياً، ويحافظ على الفكرة الخاصة: **هوية سيادية، خصوصية صادقة، تشغيل محلي، وإدارة خاضعة للمساءلة.**
