# فرق إعدادات البوابة المقترح — DINSTAR UC2000-VE

**التاريخ:** 2026-08-23
**الحالة:** بانتظار اعتماد المستخدم — لا يُنفَّذ أي تغيير أو حفظ أو إعادة تشغيل قبل موافقة صريحة منفصلة.

---

## 1) حالة الفحص اللحظي (قراءة فقط)

| البند | النتيجة |
|---|---|
| حزمة RED الكاملة (backend/pstn-gateway/proxy/db/cache/sfu/turn/admin) | تعمل — health UP |
| البوابة `192.168.11.2` | **غير قابلة للوصول** (ping timeout + TCP 443 مرفوض) وقت الفحص |
| الأثر المؤقت | Heartbeat سيوسمها OFFLINE في الأسطول؛ لا مكالمات/SMS حتى عودتها |

**إجراء مطلوب منك قبل أي شيء:** تأكد أن البوابة موصولة بالكهرباء والشبكة (192.168.11.x) وأن كابل Ethernet متصل، ثم أخبرني لإعادة الفحص الحي.

## 2) التغييرات المقترحة (كل بند بسببها ومخاطرها)

### أ. الوقت/NTP — أولوية عالية (بند todo المعلق)
- **أين:** واجهة الويب ← `System` ← `Setting`
- **التغيير:** Time Zone = `GMT+3` (Asia/Aden — الجهاز لا يدعم DST رسمياً)، تفعيل `Enable built-in NTP server` وإضافة خادم `pool.ntp.org` (أو `time.google.com`)
- **السبب:** CDR وسجلات SMS بتوقيت خاطئ تفسد الترتيب والمطابقة مع سجلات Backend
- **ملاحظة رسمية:** بعد الحفظ **يلزم إعادة تشغيل الجهاز** لتطبيق NTP (دليل Dinstar الرسمي «How to Get the Right System Time of UC2000»)

### ب. مرور المكالمة الواردة فوراً — أولوية قصوى لهدف «الاستقبال المباشر»
- **أين:** `Call Configuration` ← `Service Parameter`
- **التغيير:** `Do Not Answer GSM Incoming Call for Hotline` = **Yes**
- **السبب:** الافتراضي يجعل الجهاز **يرد على المتصل ويشغّل رسالة «Please dial the extension»** ثم يوجّه — تأخير + إزعاج. بـ Yes تمرّ المكالمة رائنةً فوراً إلى Asterisk ← التطبيق
- **مخاطرة:** منخفضة — قابل للعكس بنفس الصفحة

### ج. تحقق قراءة-فقط (لا حفظ): API الإصدار الجديد مفعّل
- **أين:** `Mobile Configuration` ← `Basic Configuration`
- **المطلوب:** `new-version API = enabled` — شرط عمل HTTP API الذي يبني عليه Backend كل شيء (send_sms/get_port_info...)

### د. تحقق قراءة-فقط: Tel→IP Routing
- **أين:** `Routing Configuration` ← `Tel→IP Routing`
- **المطلوب:** مسار من Port Group إلى IP Trunk موجّه لعنوان الكمبيوتر `192.168.11.131:5060` لكل مجموعة منافذ مستخدمة
- **السبب:** بدونه لا تصل مكالمة GSM واردة إلى Asterisk أصلاً

### هـ. SIP Profile (تحقق ثم ضبط عند الحاجة)
- Codecs: PCMA/PCMU أولاً (خبرة المنتديات الإنتاجية)، DTMF = RFC2833، NAT Traversal = **Disable** (شبكة LAN محلية)

## 3) ما لا نغيّره نهائياً (سياسة المشروع)
- لا تعديل SIP Server في الجهاز إلا بقرار منفصل (مسؤولية Asterisk عن الصوت)
- لا reboot بدون اعتماد + توثيق وقت
- لا SMS فعلي قبل اعتماد رقم الاختبار ومنفذه
- كل خطوة تُطبَّق يدوياً من واجهة الويب بخطوات أجهزها لك — لا كتابة إعدادات عبر API غير موثق

## 4) تسلسل التنفيذ بعد الاعتماد
1. (أنت) تأكد وصول البوابة → (أنا) فحص حي للمنافذ والإشارة والوقت
2. (أنت) طبّق «ب» من صفحة Service Parameter واحفظ — لا إعادة تشغيل مطلوبة لهذا البند غالباً
3. (أنت) طبّق «أ» NTP/Time Zone واحفظ ثم أعد تشغيل الجهاز في وقت متفق عليه
4. (أنا) تحقق قراءة-فقت: الساعة مضبوطة + المنافذ مسجلة + الإشارة سليمة
5. (معاً) رسالة SMS اختبارية واحدة عبر المنفذ المتفق عليه إلى رقمك + متابعة النتيجة والتسليم
