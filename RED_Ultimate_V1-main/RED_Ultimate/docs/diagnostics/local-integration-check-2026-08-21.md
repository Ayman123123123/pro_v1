# تحقق التكامل المحلي — 21 أغسطس 2026

## النتيجة

تم تنفيذ تحقق محلي قائم على الخدمات الفعلية الجارية. جميع خدمات RED الأساسية اللازمة لمسار التطبيق كانت تعمل وحالتها الصحية `healthy`. كما استجاب proxy المحلي على منفذ `8088` بنجاح لنقطة health العامة، بينما أعادت نقطة API المحمية `401` كما هو متوقع من دون token. يثبت ذلك أن حاجز المصادقة يعمل ولم يتم تجاوزه أثناء التحقق.

| العنصر | الحالة المرصودة | وسيلة التحقق | النتيجة |
|---|---|---|---|
| `red-backend` | `running`, `healthy` | Docker healthcheck | ناجح |
| PostgreSQL `red-db-sql` | `running`, `healthy`؛ المنفذ المحلي `5432` | Docker وTCP | ناجح |
| MongoDB `red-db-nosql` | `running`, `healthy`؛ المنفذ المحلي `27017` | Docker وTCP | ناجح |
| Redis `red-cache` | `running`, `healthy`؛ المنفذ المحلي `6379` | Docker وTCP | ناجح |
| MinIO `red-storage` | `running`, `healthy`؛ المنفذان المحليان `9000/9001` | Docker وTCP | ناجح |
| SFU `red-media-sfu` | `running`, `healthy` | Docker healthcheck | ناجح |
| TURN `red-turn` | `running`, `healthy` | Docker healthcheck | ناجح |
| Proxy `red-proxy` | `running`, `healthy` | Docker healthcheck | ناجح |
| `GET /actuator/health` عبر `http://127.0.0.1:8088` | HTTP `200` | طلب قراءة فقط | ناجح |
| `GET /api/health` عبر proxy | HTTP `401` | طلب قراءة فقط | ناجح؛ endpoint محمي كما يجب |

> لم تُنشأ حسابات اختبار، ولم تُرسل رسائل، ولم تُنشر حالات أو منشورات، ولم تُنشأ غرف أو بثوث في قاعدة البيانات المحلية خلال هذا الفحص. بقي التحقق غير متلف للبيانات.

## سيناريو القبول الوظيفي التالي

تحتاج السيناريوهات التالية إلى حسابين محليين معتمدين ومخصصين للاختبار، أو إلى موافقة صريحة على إنشاء حسابات اختبار قابلة للحذف. لم تُنفذ بالبيانات الحية أو بأي حساب غير محدد.

| الترتيب | المسار | معيار القبول الفعلي | الحالة |
|---:|---|---|---|
| 1 | التسجيل → انتظار الموافقة → الدخول | تتسلم الهوية token صالحاً بعد الاعتماد، ولا يمكن الدخول قبل الاعتماد | معلق على حسابات اختبار معتمدة |
| 2 | جهة اتصال متبادلة → صداقة | يظهر المستخدم في خلاصة `FRIENDS` فقط بعد تحقق العلاقة المتبادلة | معلق على حسابين اختبار |
| 3 | منشور عام/للأصدقاء → إعجاب/تصويت | تظهر الرؤية الصحيحة، ويعمل زر طلب الصداقة بدلاً من المتابعة | معلق على حسابين اختبار |
| 4 | حالة نصية/صوتية → عرض → خصوصية | تحفظ الحالة وتظهر للمستحقين فقط، مع اسم المالك وتنسيق الوقت العربي الصحيح | معلق على حسابين اختبار ووسيط صوت صغير |
| 5 | مؤتمر خاص → دخول صحيح/خاطئ | لا يُسمح بالدخول بلا صلاحية أو كلمة مرور صحيحة، ولا يمكن الاستيلاء على room ID | معلق على حسابين اختبار |
| 6 | بث خاص → دخول | كلمة المرور إلزامية للمشاهدة الخاصة ولا يوجد مسار تجاوز | معلق على حسابين اختبار |
| 7 | Android على جهاز/محاكي | لا يوجد زر ميت في مسارات الحالات والمنشورات والمؤتمرات | معلق على بناء APK الأصلي بعد تسوية المكونات المستبعدة أو تشغيل APK من نسخة تحقق مناسبة |

## القيود المحترمة

لم يتم التفاعل مع DINSTAR أو PSTN أو SMS أو مكالمات المحادثات الخاصة. كما لم تُنفذ هجرة قاعدة بيانات أو نشر أو تشغيل service دائم جديد. لا يثبت فحص health وحده صحة تفاعل واجهة Android مع الخادم؛ لذلك تبقى السيناريوهات أعلاه بوابة قبول صريحة قبل staging أو إطلاق أي نسخة.

## الخلاصة

البنية المحلية الأساسية سليمة وقابلة لاستقبال اختبار قبول مصادق عليه. الاختبار التالي يجب أن يستخدم حسابات اختبار محلية معتمدة وموسومة بوضوح، ثم يحذف بياناتها أو يعزلها بعد التحقق.
