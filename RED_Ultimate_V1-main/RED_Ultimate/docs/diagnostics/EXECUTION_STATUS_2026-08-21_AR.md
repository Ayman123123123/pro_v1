# تقرير حالة تنفيذ RED Ultimate

**التاريخ:** 21 أغسطس 2026  
**النطاق:** تحسينات التطبيق والخادم ولوحة الإدارة ضمن القيود المتفق عليها.  
**المستبعد صراحةً:** DINSTAR، PSTN، SMS، ومكالمات المحادثات الخاصة الصوتية والمرئية.  
**حالة النشر:** لم يتم تنفيذ نشر أو migration أو إطلاق عام.

## الملخص التنفيذي

اكتملت مراجعة التحقق في هذه الجولة، وثُبتت صحة تحسينات النطاق المسموح في بيئة تحقق معزولة. عائق KSP السابق لم يكن ناتجاً عن عدم توافق الإصدارات؛ اكتملت اعتمادات Signal الكبيرة، وحُمّل معالج Room بنجاح. كما أن تشغيل Gradle مع إعادة استخدام configuration cache تالف أظهر `StreamCorruptedException`، بينما تجاوزته إعادة التشغيل مع `--no-configuration-cache` ووصلت إلى تجميع Kotlin الحقيقي.

يبقى بناء Android في شجرة العمل الأصلية غير مؤهل للإطلاق، لا بسبب حالات التطبيق أو المنشورات أو المؤتمرات، بل بسبب مراجع مصدر غير مكتملة في ملفات DINSTAR/PSTN/SMS المستبعدة من النطاق. لم تُعدّل هذه الملفات ولم يُجرَ reset لأي فرق محلي. بدلاً من ذلك، أثبتت نسخة تحقق معزولة أن تحسينات النطاق المسموح تجتاز تجميع Kotlin واختبارات الوحدة: **221 اختباراً في 50 حزمة، بلا فشل أو أخطاء أو اختبارات متجاوزة**.

| المجال | النتيجة | الحالة |
|---|---|---|
| اختبارات الخادم الكاملة | `BUILD SUCCESSFUL` في جولة التحقق السابقة | ناجح |
| فحص لوحة الإدارة | `npm run check` ناجح في جولة التحقق السابقة | ناجح |
| Signal وRoom KSP | الاعتمادات مكتملة ومعالج Room يعمل | ناجح |
| Android في نسخة التحقق المسموح بها | تجميع Kotlin واختبارات وحدة 221/221 | ناجح |
| Android في الشجرة الأصلية كاملةً | محجوب بتناقضات DINSTAR/PSTN/SMS | غير مجتاز |
| تكامل البنية المحلية | الخلفية وقواعد البيانات ووسيط الوسائط وTURN وProxy صحية | ناجح جزئياً |
| سيناريو منتج مصادق عليه | يحتاج حسابي اختبار معتمدين وسيناريو قبول فعلي | معلق |
| staging وrollback | دليل قابل للتنفيذ، من دون نشر أو backup حي بعد | جاهز تشغيلياً، غير منفذ |

## ما اكتمل ضمن النطاق

تمت إضافة وتحسين مسارات الحالات، والمجموعات، والرسائل، والبث المباشر، والمؤتمرات، والمنشورات في الخادم والتطبيق. شملت النتيجة توحيد خصوصية الحالات، دعم النص والصوت، حماية cache المالك، وتنسيق الوقت العربي، وضبط استهلاك دعوات الانضمام للمجموعات، وتنظيف الرسائل ذاتية الاختفاء وفق `disappearAt` الحقيقي، وحماية البث الخاص بكلمة مرور، وتحسين تجزئة كلمات مرور الغرف، وحماية الغرف الخاصة من الاستيلاء على المعرّف.

كما تحول مسار المنشورات من مفهوم «المتابعة» إلى مفهوم «الأصدقاء» في الخلاصة والواجهة، مع طلب صداقة وتدقيق ملكية الوسائط. على Android، شملت التحسينات الموثقة الحالات والمنشورات وتجربة المجموعات والرسائل الصوتية والفراغات البصرية، مع اختبارات وحدة داعمة للحالات. لم تُغير إصدارات Kotlin أو AGP أو KSP، ولم يُمس النطاق المستبعد.

## التحقق الفعلي

| فئة التحقق | التنفيذ الفعلي | النتيجة |
|---|---|---|
| Gradle cache | تم التحقق من ملفات `libsignal-android` و`libsignal-client` المكتملة | لا تنزيلات ناقصة |
| KSP | ظهر تحميل `androidx.room.RoomKspProcessor` ووصل build إلى Kotlin | العائق السابق زال |
| Android scoped build | نسخة Git تحقق عزلت كل DINSTAR/PSTN/SMS ومسار PSTN في IncomingCallActivity | `compileDebugKotlin` ناجح |
| Android unit tests | قراءة ملفات JUnit الناتجة من `testDebugUnitTest` | 221 نجاح، 0 فشل، 0 خطأ |
| البنية المحلية | Docker healthchecks لـ backend وPostgreSQL وMongoDB وRedis وMinIO وSFU وTURN وproxy | كلها `healthy` |
| API عبر proxy | `GET /actuator/health` = 200 و`GET /api/health` = 401 | health سليم وAPI محمي |

## العائق الحقيقي أمام بوابة Android الأصلية

الأخطاء التي تمنع البناء الكامل في الشجرة الأصلية تقع في ملفات مستبعدة من النطاق. تتضمن مراجع PSTN غير محلولة في `DinstarViewModel.kt`، وواجهات غير متسقة في `PstnEventSocket.kt` و`SmsViewModel.kt` و`SmsConversationsScreen.kt`، واعتماد `IncomingCallActivity` على امتداد PSTN محلي. هذه ليست أخطاء ناتجة عن تحسينات القصص أو المنشورات أو المؤتمرات.

> لا يمكن التصريح بأن Android الأصلي «جاهز للإطلاق» ما لم يصبح تجميعه الكامل ناجحاً. ولتحقيق ذلك مع الحفاظ على النطاق، يحتاج مالك المشروع إلى اختيار أحد مسارين: السماح بإصلاح توافق مصدر محدود في المكونات المستبعدة، أو عزلها رسمياً في build variant/module لا يدخل artifact الإصدار الحالي. لا ينبغي القيام بأي منهما ضمن نطاق الاستبعاد الحالي من دون قرار صريح.

## مراجعة `RedDashboard.kt`

الملف يحوي فروقاً محلية كبيرة ومصنفة الآن. الفروق التي توافق النطاق تشمل تبويب الأصدقاء وطلب الصداقة، ضبط صلاحية شاشة الإدارة، شريط التنقل، استرجاع اختفاء رسائل المجموعات، دعم الوسائط المتعددة في رسائل المجموعات، وحالة المحادثة الفارغة وتنزيل الصوت المخصص. أما أسطح `PSTN_CONFIG` وDINSTAR/SMS فتظل مؤجلة ويجب فصلها عن تغيير الإصدار قبل الدمج. لم يُعد ضبط الملف ولم تُفقد فروقه المحلية، وفحص `git diff --check` نظيف.

## التكامل وstaging

البنية المحلية تعمل فعلياً، لكن اختبار رحلة المستخدم الكاملة لا يزال معلقاً على حسابين اختبار معتمدين ومخصصين للاختبار. لم تُنشأ حسابات أو منشورات أو حالات أو غرف تجريبية كي لا تتغير بيانات البيئة من دون تسمية حسابات الاختبار ونطاق حذفها.

تم إعداد دليل staging وbackup وrollback. يشترط الدليل manifest للصور وGit SHA ونسخ PostgreSQL وMongoDB وRedis وMinIO، والتحقق من الاستعادة في بيئة معزولة، وخطة رجوع مبنية على image digests وعدم استعادة بيانات حيّة قبل نجاح restore check. لا توجد عملية نشر أو نسخة احتياطية حيّة تم تنفيذها في هذه الجولة.

## قرار بوابات القبول

| بوابة الإطلاق المتفق عليها | القرار |
|---|---|
| بناء Android واختبارات الوحدة في الشجرة الأصلية | **لا تمر** بسبب ملفات النطاق المستبعدة |
| اختبارات الخادم الكاملة | تمر |
| سيناريوهات تكامل موثقة بنتائج حقيقية | تمر للبنية؛ رحلة المستخدم المصادق عليها معلقة |
| اختبار جهاز/محاكي بلا أزرار ميتة | معلق |
| الفروق المحلية مفهومة ومصنفة | تمر |
| backup وrollback قبل النشر | الخطة تمر؛ التنفيذ واستعادة الاختبار معلقان قبل staging |

**الحكم النهائي:** لا نشر في هذه المرحلة. يستمر العمل بأمان على النطاق المسموح، لكن الوصول إلى staging أو إصدار يتطلب أولاً قراراً صريحاً بشأن قابلية بناء مكونات DINSTAR/PSTN/SMS المستبعدة، ثم اختبار رحلة المستخدم والجهاز الفعلي.

## الخطوة الحاسمة التالية

ينبغي اعتماد قرار نطاق واحد قبل مواصلة بوابة Android الأصلية: إما السماح بإصلاح build-only محدود لتناسق DINSTAR/PSTN/SMS من دون إضافة أي ميزة، أو تعريف artifact/variant للإصدار يستبعدها رسمياً. بعد القرار، ينفذ الاختبار المصادق عليه بالترتيب: تسجيل، موافقة، دخول، صداقة، منشورات، حالات، مؤتمر، بث، ثم اختبار Android على جهاز أو محاكي.
