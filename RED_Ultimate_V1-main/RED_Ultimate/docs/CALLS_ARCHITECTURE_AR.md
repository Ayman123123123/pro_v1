# معمارية المكالمات في RED - أفضل من واتساب وتيليجرام

## نظرة عامة

RED Sovereign يدعم **9 أنواع مكالمات** بمعمارية موحدة حديثة، كل نوع له عمله الأساسي المخصص والواجهة المناسبة له.

---

## 1. أنواع المكالمات التسعة

### 1.1 مكالمة فردية صوتية (ONE_TO_ONE_AUDIO)
**العمل الأساسي**: مكالمة صوتية مشفرة E2EE بين شخصين
**الواجهة**: شاشة مكالمة بسيطة - صورة المتصل + زر كتم + سماعة + إنهاء
**التقنية**: WebRTC P2P عبر SFU للـ NAT traversal + TURN
**الرنين**: FCM high-priority + Full-screen intent + TelecomManager + كل الشبكات المحلية
**الشبكات**: كل الشبكات المحلية (WiFi, Ethernet, Mobile, VPN, Hotspot) + إنترنت

```
المستخدم A → إنشاء عرض SDP → إرسال عبر WebSocket /ws/calls
          → إرسال FCM + مكالمات محلية لكل أجهزة B
          → B يرن على كل الشبكات
          → قبول → تبادل ICE → اتصال P2P أو عبر SFU
```

### 1.2 مكالمة فردية فيديو (ONE_TO_ONE_VIDEO)
**العمل الأساسي**: مكالمة فيديو E2EE مع مشاركة شاشة اختيارية
**الواجهة**: فيديو كبير للطرف الآخر + صغير للذات + أزرار تحكم عائمة
**التقنية**: WebRTC VP8/VP9/H264 + Simulcast + SFU routing
**الرنين**: نفس الصوتية + معاينة فيديو

### 1.3 مكالمة جماعية صوتية/فيديو (GROUP_CALL)
**العمل الأساسي**: مكالمة جماعية حتى 32 مشارك في مجموعة موجودة
**الواجهة**: شبكة صور (Grid) + مؤشر متحدث + كتم جماعي + رفع يد
**التقنية**: SFU Media Server - كل مشارك يرسل مرة ويستقبل N-1
**الحد**: 32 مشارك، كلهم في نفس المجموعة
**الرنين**: إشعار جماعي لكل أعضاء المجموعة + رنين على كل الشبكات

```
المجموعة G (32 عضو) → منشئ يبدأ مكالمة جماعية
                    → SFU ينشئ Room: group_{groupId}_{timestamp}
                    → إرسال FCM + WS لكل الأعضاء
                    → كل عضو يرن وينضم عبر SFU
```

### 1.4 مؤتمر صوتي/فيديو (CONFERENCE)
**العمل الأساسي**: مؤتمر كبير حتى 100 مشارك، ليس مرتبط بمجموعة
**الواجهة**: قائمة متحدثين + Grid قابل للتبديل + مشاركة شاشة + تسجيل + رفع يد + غرف فرعية
**التقنية**: SFU + تسجيل اختياري + إدارة أدوار (مضيف/متحدث/مستمع)
**الحد**: 100 مشارك
**المميزات**: رابط دعوة، PIN، انتظار، تسجيل سحابي، غرف فرعية

### 1.5 بث مباشر (LIVE_STREAM)
**العمل الأساسي**: بث واحد-إلى-كثير، متحدث واحد وجمهور كبير
**الواجهة**: فيديو كبير للمتحدث + دردشة مباشرة + تفاعلات + عدد مشاهدين
**التقنية**: SFU → HLS/DASH transcoding + CDN edge
**الحد**: متحدث 1-5، مشاهدين غير محدود

### 1.6 غرفة صوتية (VOICE_SPACE / Audio Space)
**العمل الأساسي**: غرفة صوتية مثل Clubhouse/Twitter Spaces
**الواجهة**: صور دائرية للمتحدثين + مستمعين + رفع يد + تفاعلات صوتية
**التقنية**: SFU audio-only + إدارة أدوار ديناميكية

### 1.7 مكالمة PSTN (PSTN_CALL)
**العمل الأساسي**: مكالمة من التطبيق إلى رقم هاتف عادي (يمني ودولي)
**الواجهة**: لوحة أرقام + سجل مكالمات + رصيد + تسعير
**التقنية**: SIP → Asterisk/FreeSWITCH → PSTN Gateway → شبكة هاتف يمنية
**التسعير**: يمني محلي، دولي
**المميز**: لا يوجد في واتساب/تيليجرام بهذا الشكل المتكامل

### 1.8 مكالمة LAN P2P بدون إنترنت
**العمل الأساسي**: مكالمة مباشرة بين جهازين على نفس الشبكة المحلية بلا إنترنت
**الواجهة**: نفس الفردية + شارة "P2P LAN - بلا إنترنت"
**التقنية**: اكتشاف mDNS + اتصال WebRTC مباشر عبر IP محلي + ICE host candidates فقط
**الشبكات**: WiFi نفس الشبكة، Ethernet، Hotspot
**المميز**: يعمل بلا إنترنت - لا يوجد في واتساب/تيليجرام

```
جهاز A (192.168.1.10) → فحص 192.168.1.0/24 + mDNS _younes._tcp
                    → وجد B (192.168.1.15) عبر NSD
                    → اتصال WebRTC مباشر: 192.168.1.10 ↔ 192.168.1.15
                    → بلا خادم وسيط، بلا إنترنت
```

### 1.9 مكالمة طوارئ/مهمة (EMERGENCY / Priority Call)
**العمل الأساسي**: مكالمة ذات أولوية قصوى تتجاوز عدم الإزعاج
**الواجهة**: شاشة حمراء + اهتزاز قوي + تجاوز صامت
**التقنية**: FCM high-priority + Full-screen + تجاوز DND + كل الشبكات المحلية

## 2. نظام التوصيل الموحد (Unified Call Delivery)

### المشكلة في واتساب/تيليجرام
- يعتمد على FCM فقط → يفشل في الصين/إيران/شبكات محجوبة
- لا يرن إذا الجهاز على WiFi محلي فقط بلا إنترنت
- لا يدعم P2P LAN

### حل RED الموحد

```kotlin
class UnifiedCallDeliveryService {
    fun deliverCall(toUserId: String, callType: CallType) {
        // 1. WebSocket فوري إذا متصل
        websocketManager.sendCallInvite(toUserId, sdp)
        
        // 2. FCM High-Priority + Full-Screen
        fcmService.sendVoipPush(
            toUserId, 
            priority = HIGH,
            fullScreen = true,
            bypassDnd = true
        )
        
        // 3. كل الشبكات المحلية (UDP Broadcast + mDNS)
        lanCallDiscovery.broadcastCallInvite(toUserId)
        
        // 4. إعادة محاولة عبر كل الشبكات
        unifiedNetworkManager.tryAllNetworks { network ->
            network.sendCallInvite(toUserId)
        }
        
        // 5. PSTN fallback إذا فشل الكل (اختياري)
        if (isEmergency) pstnGateway.callPhoneNumber(toUserId)
    }
}
```

### مسارات الرنين الـ 6
1. **WebSocket** (`/ws/calls`) - فوري إذا التطبيق مفتوح
2. **FCM High-Priority** - حتى لو التطبيق مغلق، مع Full-screen intent
3. **TelecomManager** - يظهر كـ مكالمة نظام حقيقية
4. **LAN Broadcast** - UDP على 5353/5354 لكل الشبكة المحلية
5. **mDNS/NSD** - اكتشاف الأجهزة وإرسال مباشر
6. **PSTN** - للطوارئ، يتصل برقم الهاتف

## 3. الواجهات المناسبة لكل نوع

### 3.1 فردية صوتية
- خلفية متدرجة حسب المتصل
- صورة كبيرة 120dp
- اسم + حالة (يرن/متصل/مدة)
- أزرار: كتم، سماعة، لوحة، إضافة، إنهاء أحمر كبير

### 3.2 فردية فيديو
- فيديو طرف آخر يملأ الشاشة
- فيديو ذاتي صغير 100x140 قابل للسحب
- أزرار عائمة شفافة: كاميرا، ميك، تبديل، إنهاء
- شارة E2EE + جودة + شبكة

### 3.3 جماعية 32
- Grid 2x2 لـ 4، 3x3 لـ 9، قائمة تمرير لـ 32
- كل خلية: صورة + اسم + ميكروفون + متحدث (حدود خضراء)
- شريط علوي: اسم المجموعة + عدد + مدة
- شريط سفلي: كتم، كاميرا، سماعة، إضافة، مغادرة

### 3.4 مؤتمر 100
- وضعان: Grid و Speaker
- Grid: صفحات 12 كل صفحة
- Speaker: متحدث كبير + شريط صغير للآخرين
- لوحة جانبية: مشاركين، دردشة، رفع يد، تسجيل
- تحكم مضيف: كتم الكل، طرد، قفل

### 3.5 بث مباشر
- فيديو 16:9
- عداد مشاهدين + مدة + تفاعلات طائرة
- دردشة مباشرة بجانب/أسفل
- للمتحدث: كاميرا، ميك، مشاركة شاشة، إنهاء

### 3.6 مساحة صوتية
- دائرة كبيرة للمتحدثين (3-10)
- شبكة للمستمعين (100+)
- زر رفع يد كبير
- تفاعلات: 👏 ❤️ 😂

### 3.7 PSTN
- لوحة أرقام يمنية
- عرض رصيد وتسعير
- سجل مكالمات PSTN
- جودة: HD/3G/PSTN

### 3.8 P2P LAN
- نفس الفردية + شارة زرقاء "P2P LAN • بلا إنترنت"
- عرض IP محلي
- جودة ممتازة (لا تأخير إنترنت)

## 4. التقنيات الحديثة المستخدمة

### 4.1 WebRTC
- **P2P**: للفردية والـ LAN
- **SFU**: للجماعية والمؤتمر والبث
- **Codecs**: VP9, H264, Opus
- **Simulcast**: جودات متعددة
- **ICE**: Host (P2P LAN) + Srflx (STUN) + Relay (TURN)

### 4.2 شبكات
- **mDNS/NSD**: اكتشاف خوادم وأجهزة على LAN
- **IP Scanning**: فحص 192.168.x.x و 10.x.x.x
- **Multi-path**: محاولة كل الشبكات بالتوازي
- **P2P**: اتصال مباشر بلا خادم

### 4.3 رنين
- **FCM**: High-priority + Full-screen + Category: CALL
- **TelecomManager**: ConnectionService + Self-managed
- **Notification**: Full-screen intent + Ongoing + Bypass DND
- **LAN**: UDP Broadcast + mDNS

### 4.4 أمان
- **E2EE**: DTLS-SRTP للـ WebRTC
- **Signal**: للرسائل
- **TOFU**: للتحقق الأولي
