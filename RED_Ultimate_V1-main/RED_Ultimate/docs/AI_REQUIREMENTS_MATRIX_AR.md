# مصفوفة المتطلبات مقابل المشروع الأصلي

| المطلب | الوحدة الأصلية المرشحة | ما ثبت وجوده | ما يجب التحقق منه قبل التطوير |
|---|---|---|---|
| الرسائل الخاصة | `backend-server/.../messaging` + واجهات المحادثة داخل `app/` | خدمة رسائل متقدمة، تثبيت رسائل، وتشفير موروث | مسار الشاشة الرسمي، عقود WebSocket، وحالات الفشل في الجهاز غير المعتمد. |
| المجموعات | `backend-server/.../groups` وطبقات Signal للمجموعات | `GroupController` و`GroupService` وأدوار وصلاحيات | مطابقة واجهة الإدارة مع E2EE وSender Keys وعدم كشف الرسائل. |
| المكالمات الفردية والجماعية | `backend-server/.../calls` + `media-sfu` | سجل مكالمات، ICE، تذاكر SFU، مؤتمرات | اختبار النقل الحقيقي، الصلاحيات، جودة الشبكة، ودورة حياة الغرفة. |
| البث المباشر | `LiveStreamController` و`LiveStreamService` وWebSocket | إنشاء/بحث/انضمام/إيقاف ودعوات ومشاهدون | هل الوسائط تمر عبر SFU/خدمة نشر فعلية؟ وكيف تُدار المحادثة والإشراف؟ |
| المؤتمرات العامة | `ConferenceController` وWebSocket | غرفة، دعوات، أعضاء، طابور/صلاحيات بحسب العقود | اختبار المضيف والمتحدث والمستمع والإغلاق والاستعادة. |
| المنشورات والحالات | `AdminSocialController` و`PostsManagement` و`StatusController` | إدارة اجتماعية ولوحة منشورات وحالة مستخدم | تحديد طبقة المنتج على Android وربطها بنطاق الأصدقاء/عام والخصوصية. |
| SMS وDINSTAR | `DinstarController` و`DinstarSmsController` و`PstnCallController` | خدمات بوابات وأجهزة ومسارات SMS/PSTN | عدم تشغيل أي طلب مكلف أو حساس دون بيانات الجهاز الحقيقية واختبار آمن. |
| لوحة الإدارة | `admin_dashboard/src/pages` | صفحات للمستخدمين، المجموعات، المنشورات، SMS، المكالمات، التشخيص | توحيد الصلاحيات، الحالات الفارغة، وعدم كشف محتوى E2EE. |
| الهاتف اليمني | `DinstarModelProfile` و`DinstarHardwareService` وملفات PSTN | يوجد دعم/تحليل للبوابات، وليس دليلاً على جهاز هاتف محدد | يلزم اسم الطراز ورابط/دليل الجهاز وطريقة الاتصال المعتمدة قبل كتابة تكامل خاص. |

## ترتيب التطوير المقترح

يبدأ العمل بتثبيت مسارات البناء والاختبارات للمشروع الأصلي، ثم تحسين شاشات Android التي تعرض الرسائل والمجموعات والمكالمات والحالات، مع عدم تغيير البروتوكول إلا عند الحاجة. بعد ذلك تُراجع عقود الخادم ولوحة الإدارة في حزم صغيرة، ثم تُختبر المسارات الحية في بيئة Compose. أي ميزة تعتمد على جهاز خارجي أو مزود اتصال أو نقل وسائط حقيقي ستبقى خلف بوابة تحقق واضحة حتى تتوفر بيئة الاختبار المناسبة.
