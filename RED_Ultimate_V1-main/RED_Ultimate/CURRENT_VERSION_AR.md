# النسخة الحالية ومسار التشغيل

## النسخة التي يجب العمل عليها

اعتمد هذا المجلد فقط كمصدر المنتج الحالي:

```text
RED_Ultimate_V1-main/RED_Ultimate
```

آخر تعديل لمكوناته الفعلية كان في 8 سبتمبر 2026. لا تُشغّل أو تدمج مباشرةً
`_backup_*` أو `_SNAPSHOT_*` أو `_red_ultimate_verify` أو `PRO_unpacked`؛ فهي
نسخ احتياطية أو لقطات أو مصادر مرجعية وليست منتجًا آخر.

## ما يدخل المنتج

- `red-app/`: تطبيق Android الوحيد (`:app`).
- `backend-server/`: خادم Spring/Kotlin.
- `admin_dashboard/`: لوحة الإدارة React.
- `media-sfu/`: وسائط ومكالمات الإنترنت.
- `docker-compose.yml`: نقطة تشغيل الخدمات الواحدة.

`app/` و`android/` و`core/` و`lib/` و`feature/` مصادر تاريخية؛ لا تضفها إلى
Gradle ولا تنسخ منها ملفات تلقائيًا. انقل إصلاحًا محددًا منها فقط بعد اختبار
وتوثيق المصدر والوجهة.

## التشغيل الصحيح

1. ثبّت Node.js 22 LTS (أو 20.19+). Node 16 لا يستطيع بناء Vite 7 للوحة الإدارة.
2. من هذا المجلد شغّل `scripts/local-first-run.ps1` مع عنوان IP الحقيقي لجهاز
   الخادم. ينشئ ذلك إعداد الخدمات وAPK موجهًا إلى الخادم نفسه.
3. عند بناء APK يدويًا، مرر `-ServerUrl http://SERVER_IP:8088` إلى
   `scripts/build-apk.ps1`. لا توجد قيمة افتراضية لشبكة هاتف حقيقية.
4. لا تستخدم `npm run dev:server` أو ملفات `mock-backend.cjs` كنظام تشغيل؛ إنها
   أدوات تاريخية ويجب أن تبقى خارج مسار Docker.

## قاعدة الدمج

لا يعني "أحدث ملف" أنه الإصلاح الصحيح. كل إضافة تمر بهذا الترتيب:

1. عرّف الوظيفة المطلوبة والعقدة التي تملكها (Android أو backend أو dashboard).
2. أضفها إلى المكون القانوني فقط.
3. ابنِ واختبر العقدة ثم اختبرها مع Docker.
4. وثّق النتيجة أو التراجع المطلوب.
